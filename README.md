## 一、它解决什么

AstrBot 原本的通病：

1. **回复像机器**：一次吐一大段，没有停顿，句末带句号，还爱加 emoji。
2. **没有记忆**：三天前说过的事，第四天完全不记得。
3. **看不懂特殊消息**：合并转发、引用、卡片、语音，进模型时全成了空白。
4. **不会用工具**：天气、番剧、MC 状态都得用户自己去查。
5. **碰不到 QQ 原生能力**：签名、名片、资料、空间，全在插件之外。

这个插件就是逐条补这五个洞。

## 二、八个模块

### 1. 拟人化（`humanize/`）

- **回不回**：打分制。私聊必回；群聊看是否被点名、是否问句、群里是否太吵、是不是刚回过。分不够就按概率抽签——所以它有时候看到了不说话。
- **连续对话窗口**：回过一次后 5 分钟内阈值降低 15，形成"聊起来"的连贯感。
- **分句**：按句号问号切，短碎片合并，长句按逗号二次切，20% 概率把两句并成一句，15% 概率拆开一句。短回复不切（一两句话本来就该一口气说完）。
- **节奏**：首条前 `1.2 + 0.02×字数` 秒（1.0~4.5），条与条之间 `0.6 + 0.09×字数` 秒，随机 ±30%。用替换 `event.send` 的方式实现，一条一抽。
- **引用**：基准 0.08，被回复 +0.15，长消息 +0.10，上限 0.35，30 秒冷却。
- **输出守卫**：去 emoji、去句末句号（保留问号感叹号）、压平换行、禁用语、重复自检。

### 2. 长期记忆（`memory/`）

```
采集 → LLM 抽取原子 → 去重合并 → 打分 → 入库
     → 召回（BM25 + 可选向量，RRF 融合）→ 注入 → 每日衰减 → 归档/遗忘 → 反思
```

- 只从**用户发言**抽事实，模型自己的话不作为事实来源（防自我强化）。
- 相似度 ≥0.86 视为重复（只强化不新增）；0.6~0.86 且带否定冲突时，新条 supersedes 旧条，旧的转归档不删。
- 注入带时间戳 + "与当前对话冲突时以当前对话为准"，同一原子 24 小时内不重复注入。
- 每日 04:00 前后反思一次，生成"我对这个人的新认识"。

**记忆等级与永久档**

五级衰减之外还有一档 `0 级 · 不可忘`：不衰减、不会被淡忘、检索永远排最前。
它不该随便进，所以判定收得比较紧（`memory/permanent.py`）：

| 判据 | 条件 |
| --- | --- |
| 明确禁令 | 有强禁止词 + **明确对象** |
| 核心关系人 | 好感度 ≥600（不足三位取排行前三）+ `kind ∈ {promise, relation, pref}` + `importance ≥ 0.9` |

「有明确对象」这条是重点：「不要动 aaa 文件夹」算，「别提了」「别管我」不算——
后者在中文里出现频率太高，一命中就进永久档，等于没有门槛。

身份锚点（名字、生日）走「至少 4 级」，硬承诺走「+1 提升」——这两类记错可以纠正，
没到「一破就出事」的程度，不占永久档。

面板「记忆 → 永久记忆」能看到全部 0 级条目，带条数、占比、命中次数，
每条可以「降成普通」或「忘掉」。

**0.5.0 起记忆会分等级**

| 等级 | 记什么 | 大概能留多久（均衡档） |
|---|---|---|
| 0 不可忘 | 有明确对象的禁令、核心关系人的关键记忆 | 永不衰减 |
| 1 随口 | 今天好热、在吗 | 一周左右散掉 |
| 2 细节 | 小事、一次性的时效信息 | 半个月 |
| 3 平常 | 工作、爱好、常去的地方 | 一两个月 |
| 4 在意 | 明确喜好、雷点、约定 | 三四个月 |
| 5 关键 | 身份、承诺、创伤 | 半年以上 |

- 等级不是模型一句话定的：模型给基础档 → 标签压上下限（身份至少 4 级、寒暄封顶 2 级）
  → 好感度微调（交心的人说的闲话更容易被记住）→ 禁区/里程碑直接定档
- **遗忘曲线**四档可选，按「距上次被想起多少天」重算保留率，幂等，不受维护频率影响
- **好感度**每天结算：记忆贡献 + 说话加成 - 冷淡扣分，单日有上限，掉分不掉穿阶段
- **用户画像**：把某个人的记忆压成一段认识 + 关键词，名额跟着好感度走
- **用户识别库**：昵称会变 QQ 号不会，提到的人名能对上人

### 3. 特殊消息（`perception/`）

| 类型 | 处理 |
|---|---|
| 合并转发 | `get_forward_msg` 展开，递归 2 层、最多 60 条，超 1200 字先摘要；**明确标注"说话人是记录里的人，不是当前用户"** |
| 引用 | 展开 3 层，区分当前发言者 / 被引用作者 / 第三方 |
| 图片 | 视觉模型描述 + 缓存（30 天同图不重复烧） |
| 语音 | STT 转写，超时降级为 `[语音]` |
| 卡片/小程序 | 解析标题与来源域名（B 站/抖音/网易云…） |
| 其他 | @、表情、戳一戳、位置、文件 |

所有增强带 6 秒总超时：宁可这轮少看一点，也不能让首响拖到十几秒。

### 4. 长夜如梦（`night/`）

让它会累、会睡、会说晚安、会做梦。

**精力**：上限 100，疲劳期（默认夜间 23:30–07:00、午间 13:00–14:30）里按分钟往下掉，
每收到一条消息再掉一点。掉到底就开始犯困。

**入睡**：进入疲劳期后再聊够 `min_turns_before_sleep` 轮，精力见底就自己睡；
另有 `latest_sleep_time` 兜底——到点无论如何都睡。

**道别**：睡前会说一句话，可以固定、可以随机、也可以让模型自己写。
说完就是真的停了，这一觉期间的消息都不回。

**唤醒**：
- `private_only`：只有在私聊里叫得醒（默认）
- `both`：群聊也能叫
- `never`：叫不醒，等自然醒

叫醒是**掷骰**的：睡着后第 y 条消息开始有机会，y 到 y+n 之间概率平分 100%，
掷中才算真醒，没掷中就继续睡。这样不会"一发消息就被吵醒"。

**爬楼**：睡着期间收到的消息会标成「未曾爬楼」，醒来要翻一遍才算真的读过，
不会出现"睡着时发生的事它当作没发生"。

**睡眠阶段**：睡着之后不是一片黑。一个周期 90 分钟，走
`刚入睡 → 浅层 → 深度 → 浅层 → 快速眼动`，一晚 4~6 次；前半夜深睡多、后半夜 REM 多
（八小时实测：深睡 17%、REM 22%、浅睡 59%）。状态栏直接显示
「深度睡眠 · 第 3 个周期 · 还有 7 分钟」，睡眠页有一条整夜的甘特条和当前时刻游标。

它不只是个标签，四处都在用它：只在 REM 段做梦、深睡时精力恢复 ×2.2、
深睡时叫醒概率打 0.45 折（喊不动）、从深睡醒和从 REM 醒的说话语气分开。
阶段不落库，按入睡时间和当前时间现算，插件重启、电脑休眠、时钟跳变都不会漂。

**做梦**：只在 REM 段做，一场觉对应四五段。按等级一天天衰减（1 级第二天就淡了，
5 级能留一周）。醒来按等级掷骰决定提不提；也可以手动「拽住」某一段，不再衰减、
永远不会被忘掉。梦按「夜」归并——凌晨三点的梦算在前一晚，符合人对"昨晚"的直觉。
想立刻看效果，梦境页右上角有「现在做一段」。

**不想让它睡**：设置里的 `night.allow_sleep` 关掉后照样算精力、照样喊累，
但永远不会真的睡过去，也不拦消息。想聊天的时候关掉它就行。

**它怎么知道自己累**：模型看到的是两段话，顺序很重要。

最后一段永远是时间（`clock.moment_line()`）：

```
现在是 2026-11-15 周日 02:40（北京时间 UTC+8）
```

这一段每轮都变，所以放在整个注入链的**最末尾**——放前面会把 prompt 前缀打散，
缓存命中率白掉。前面的记忆、人格、场景全都不受影响。

精力提示平时**不出现**。只有掉到 30 以下才冒一句，而且按 `night.allow_sleep` 分岔：

| 情况 | 说的话 |
| --- | --- |
| 能真睡 | 「你已经很困了，心里在准备休息。对方要是没有要紧事，你想早点收场」 |
| 关掉真睡 | 「你已经很困了，但还醒着愿意陪。回话会短、会慢，不用硬撑出精神来」 |

中间那些「精力还剩 55%」全去掉了——报电量式的句子模型只会照着复述，
反而不像人在说话。时间本身比任何百分比都有说服力。

**安静（1.3.0 新增）**：说了晚安，不一定要真躺下。收线命中后可以只进「安静」——
`mode` 仍然是 `awake`，不做梦、不按睡眠阶段回精力、醒来不说道别，只是这段时间不接话。

| 命中 | 安静到 |
|---|---|
| 晚安 / 睡觉吧 / 该睡了 / 去睡觉 | 下次起床点 |
| 拜拜 / 先撤 | 30 分钟 |
| 午安 / 眯一会儿 | 75 分钟 |

解除规则刻意做得简单：**只有管理员的消息计数**，群聊要 @ 或引用，默认 5 分钟内 2 条到数就醒，
不掷骰——「安静」本来就只是「别接话」，不是「睡着了」，用睡觉那套概率去解除属于用力过猛。

`night.enabled` 和 `night.allow_sleep` 都开着才走真睡；否则走安静。

**收线权限门**：谁能让它停下要过名单（`close.trigger_mode`）。

| 值 | 谁能触发 |
|---|---|
| `whitelist`（默认） | 白名单里的人，管理员始终算在内 |
| `admin` | 只有管理员 |
| `all` | 谁都能触发 |

名单填 QQ 号：私聊按对方判，群聊按说话人判；填群号则整群放行。
名单**空着**不等于谁都能停，而是退回「只有管理员能停」；判定抛异常一律按拒绝处理。

### 6. QQ 扩展（`qqext/`）

- 个性签名（`set_self_longnick` / `set_qq_profile` 兼容探测）
- 群名片、资料查询（可带"我和 TA 的关系"）
- 戳一戳（60 秒冷却）
- QQ 空间：内置直连，不依赖其它插件（详见下面「QQ 空间」一节）
- **每日说说**：一天 1~3 条，时段随机；素材抽自当天的梦、新记忆、情绪浓度高的对话，
  7 天内不复用，带隐私过滤
- **换头像**：进程内直接 `set_qq_avatar`，不用临时插件重启。头像库分「可信 / 待审」，
  她自己扒到的图必须你点头才会用；图片超限自动本地压缩

写操作（改签名、发说说、换头像）0.5.0 起默认可用，配额和过滤兜底。
想安静就把 `qzone_auto_post` 关掉，或者把每日上限改成 0。

**空间行为模式（1.3.0）** · `qq_extra.qzone_behavior_mode`

| 值 | 效果 |
|---|---|
| `off`（默认） | 只在明确要求时动手，不主动提 |
| `intent` | 可以有念头，带「最近发过什么」防重复和 6 小时冷却 |

两档都在 prompt 层注入，不改 system prompt。

### 7. 日记（`memory/diary.py`）

她自己的日记，不是给用户看的报告。

- 一天一篇，素材只来自**真实发生在身上的事**：当天的记忆按类型分桶抽样、当天和前一晚的梦、
  精力与午睡、好感度档位
- 好感度不够时，prompt 里明确「不要写具体名字」，名字也走主体库，不会乱点人
- 到点自动写（小时可配 + 每日固定抖动）；启动时补写昨天，最多一篇，不会追着补一个星期
- 模型不按 JSON 返回也不丢正文：整段当正文，心情按关键词估
- **不写数值型状态**：素材里只给感觉（「精神是满的」「有点乏」「快撑不住了」），
  prompt 里也禁掉了「精力 100」这类读数——日记是写给自己看的，没人会在里面记仪表盘数字
- **签名可配**：`diary.signature`，1-3 个字。留空则跟随当前人格名
- **重写**：面板上的「重写今天这篇」是真的重写——加 `force` 跳过「已有就返回旧文」的短路，
  用 UPDATE 覆盖正文，同时保留钉住状态
- 面板「长夜 · 日记」里翻得到，可以钉住，也可以删

### 8. 主动找人（`humanize/proactive.py`）

原来插件没有任何主动发送通道——道别语是塞在下一条回复里带出去的。这一条是新的：
`context.send_message` 直接发，绕过「装饰结果」钩子，所以分句和节奏得自己来。

- **硬否决和打分刻意分开**：睡着、免打扰、额度用完、还在冷却、关系不够熟，
  这些先一票否决；过了才进打分。不这么做的话，调一次阈值就能让它在凌晨三点冒一句
- 额度：每天总量、每会话上限、冷却分钟数；连着几条没被回就退避
- 生成失败、内容为空、跟上一句一字不差 → 不发，也不留行动记录
- 发出去的进归档，否则下一轮上下文里她不知道自己刚说过话；同时进行动日志，好感 +2
- 启动后前三分钟什么都不做——重启就冒一堆消息是最吓人的失败形态
- **安静期不动**：说了晚安之后还反过来主动戳人，比不回更怪
- 默认关闭，面板「行为 · 主动找人」里开

> [!IMPORTANT]
> **它为什么以前记不住自己说过什么**
>
> AstrBot 的 `Context.send_message()` 只负责把消息发出去，**不更新对话历史**
> （框架源码里这个函数不调 `ConversationManager.update_conversation()`，私聊没有例外通道）。
> 所以主动发出去的那句话，模型自己不知道。
>
> 插件的应对是把它写进 `msg_archive`，下一轮由 `perception._recent_context()` 捞出来注入。
> 但**注入时只按 `sender_name` 渲染**，而归档名读的是配置里那个静态人格名——
> 于是模型看到「绫: 你说饱了之后就没声了」，把它当成别人说的话，回一句「什么没有」。
>
> 1.3.0 的修法：归档名改用 `persona.display_name()`（跟随 AstrBot 人格），
> 注入时**按 `sender_id` 判角色**——`bot` 的行渲染成「我刚才说：…」，
> 并在注入块开头点明「标着『我刚才说』的是你自己发过的话」。
> 判角色看 id 不看名字，这样换人格也不会再错位。

## 三、和现有插件共存（重要）

本插件**不自建对话主循环**，是一层可插拔增强。启动时探测：

| 检测到 | 本插件行为 |
|---|---|
| `private_companion` | 拟人主链路让位，只做分句/节奏/守卫 |

| `reply_delay` | 不包装 `event.send`，避免延时叠加 |

用 `/绫 兼容` 或插件页面「设置」页可以看到当前让位结果。
强制本插件负责某块：配置 `compat.mode = force_local`。

## 四、用法

### 人设来源（三选一）

人格页顶部可以选：

| 模式 | 行为 |
|---|---|
| `builtin`（默认） | 用插件自带「绫」的人设：短句、少解释、有点懒。页面里可直接编辑、可回滚 |
| `astrbot` | 下拉选 AstrBot 里已有的人格（含默认人格）。**本插件不再注入自己的人设文本**，只补关系、当前状态、场景这三层增强 |
| `none` | 完全交给 AstrBot 默认人设，本插件连风格约束都不加 |

选 `astrbot` 时不会和框架的人设打架：人设归 AstrBot，插件只加"它知道什么"（关系远近、现在几点、在群聊还是私聊）。

### 指令

```

/绫 记忆 <词>         翻相关记忆
/绫 记住 <内容>       手动记一条（管理员）
/绫 忘掉 <词>         忘掉相关记忆（管理员）
/绫 空间 看           看空间动态
/绫 空间 发 <内容>    发一条说说（管理员）
/绫 兼容              查看共存状态
/绫 调试 开/关        决策日志
```

### 插件页面

AstrBot 后台 → 插件 → 从绫开始 → 打开页面（`pages/fromling`）。

**结构原则：每个板块的设置就在它自己的页面里，不堆在最后。** 每张配置卡只摆核心几项，
其余收进「高级设置」折叠；每页底部一个保存按钮，一次提交本页所有改动。

| 页签 | 内容 |
|---|---|
| 概览 | 活跃记忆 / 归档消息 / 决策记录 / 运行时长，模块状态，六个板块入口，最近 6 条决策 |
| 人格 | 人设来源三选一 + **随选择切换的内容区**：内置人设可编辑 / AstrBot 人格只读全文 / 默认人设说明；人格附加设置 |
| 行为 | 什么情况下回（阈值、分句、延迟、引用）、输出风格（emoji/句号/换行/字数）、看得懂什么（转发/图片/语音/卡片） |
| 记忆 | 子标签：**永久记忆**（0 级那一档单独一页，带降级和忘掉）、记忆总览、按会话分、记忆设置、记忆时间轴、等级与遗忘、好感度、主体合并 |
| 长夜 | 状态 / 睡眠 / 记忆 / 梦境 / 设置 五个标签：前四个只读，开关参数全在设置页；梦境按夜分组、字色记强度、行距记遗忘 |
| 日记 | 一天一篇的日记本，双面书页排版，可钉住、可重写、可删 |
| 设置总览 | **15 个板块 241 项配置一页摊开**，按「常改 → 少改」排序，冷门项收进「高级设置」折叠，改完一起保存 |
| 设置快照 | **纯只读**，一个可点控件都没有。核对现状、截图发人、排查「改了怎么没生效」用这一页 |
| 更新日志 | 按版本分块：问题与修复 / 新功能 / 下次更新 |
| 工具 | 工具设置（分组、限流）、已注册能力清单与试跑 |
| QQ | QQ 扩展设置、空间状态（模式/可用/写权限）与读取 |
| 系统 | 生效范围、与外部插件共存矩阵、让位策略、调试日志 |

配置项共 241 个，分布在 15 个 schema 分区里，按上面的归属拆到各页。

### QQ 空间（内置实现，不依赖其它插件）

协议细节对照 `astrbot_plugin_qzone_ultra` 与 `astrbot_plugin_private_companion` 的实现，
本插件自己直连空间接口，不必再装空间插件。

**登录态从哪来**（按优先级）：

1. 设置里手填的 `qq_extra.qzone_cookie`（协议端拿不到 cookie 时才需要）
2. 上一次拿到的 cookie（存在本地库，重启可复用）
3. 现场向 OneBot 客户端要：`get_cookies` → 退到 `get_credentials`，都没有就报错说人话

**能做什么**：

| 动作 | 接口 | 说明 |
|---|---|---|
| 读某人空间 | `GET page/qzone/feed?target=` | 走 `emotion_cgi_msglist_v6`，自己/别人都行 |
| 读好友动态流 | — | 走 `feeds3_html_more`（"最近大家发了啥"） |
| 发说说 | `POST page/qzone/publish` | 走 `emotion_cgi_publish_v6`，上限 1000 字，需先开写权限 |
| 刷新登录态 | `POST page/qzone/auth` | 重新向协议端要 cookie |

写操作默认关闭（`qq_extra.qzone_allow_write=false`），要在 QQ 页里手动打开。
登录态失效时会自动重拉一次再重试，仍然不行就把原因原样显示出来。

**给模型的三个工具**（受 `capability.groups` 控制）：

| 工具 | 分组 | 能做什么 |
|---|---|---|
| `qzone.read` | `life` | 好友动态 / 某人空间 / 单条全文 / 评论列表 / 最近访客 |
| `qzone.post` | `qzone`（需管理员） | 发说说 / 删自己 6 小时内的 |
| `qzone.interact` | `qzone`（需管理员） | 点赞 / 评论 / 回复评论 |

配套四条边界，都是刻意定死的：

- **删说说限 6 小时内**，更早的不给删（那已经是别人的回忆了）
- **访客每天一次**，反复查会留下痕迹
- **评论 id 不外泄给模型**，只回「评论好了」这类结果，不把内部标识塞进上下文
- **点赞评论只能对好友动态流里的条目**——那套接口才返回 `unikey` / `curkey`，
  对着单条说说硬点会失败，所以先判来源再决定允不允许

**说说自动配图**：正文抽情绪词 → 表情包库检索 → 上传图床 → 带图发布。
没有情绪词就不配图——配图是情绪的标点，不是装饰。任何一步失败都退回纯文本，
不会因为配不上图把说说卡死。开关 `qq_extra.qzone_image_from_meme` 以前只是面板上摆着，
现在真的被读了。

**"看谁的空间"怎么认人**（`qqext/targets.py`）：

| 用户说的 | 解析成 |
|---|---|
| 直接给号：`看看 10001 的空间` | 10001 |
| `看看我的空间` / `我空间` | 当前说话人 |
| 没说是谁，但 @ 了某人 | 被 @ 的人 |
| 没说也没 @（群里有人问"看他的空间"） | 当前说话人 |
| 昵称：`看看小山的空间` | 群成员（群名片/昵称/备注）→ 好友（备注/昵称） |

昵称是**精确优先**：有人正好叫这个就用他；只有部分匹配且命中多人时会明确报"有好几个人"
并列出候选，不会瞎猜。群成员列表和好友列表都缓存 5 分钟。

`qq_extra.qzone_read_others`（默认开）关掉后只能看说话人自己的空间。

### 管理员是谁

判定顺序（`main.py: is_admin`）：

1. **AstrBot 全局管理员**：WebUI 全局配置里的 `admins_id`，一定算
2. **插件额外管理员**：`basic.extra_admins`，一行一个 QQ 号，只作补充
3. **群主 / 群管**：默认**不算**，要开 `basic.include_group_role`

为什么不给插件单独一套完整名单：两套名单一定会打架——你在 WebUI 加了人，
插件里没加，结果他"是管理员又不是"。所以插件只存"额外的"，主名单永远跟着 AstrBot。

UI 里的位置：**系统 → 管理员**。上面只读显示 AstrBot 名单和当前生效的人，
下面可以填额外管理员、开关群管权限。

## 五、已知限制

诚实列出来，避免误期待：

1. **向量检索需要手动配置 embedding provider**，没配就走 BM25（中文 bigram，装了 jieba 更好）。
2. **群聊主动插话尚未接入**：`Decider` 的打分能力已经完整，但"自己发起一轮对话"没做
   （需要额外的主动消息链路）。**这是有意不做的**——情绪一旦能决定「要不要回」，
   角色就会开始闹脾气不理人，那是另一个产品方向。
3. **语音条未接入**：配置位和 TTS 调用点留好了，当前不会主动发语音。
4. **表情包依赖 `stealer` 插件**：接口位留了，尚未转接它的检索方法。
5. **资料卡是文本**，没有渲染成图片。
6. **流式输出不分句**（会把流式体验撕碎），只做清理。
7. **安静与睡眠是全局的**：没有「只停当前会话」这一档。睡了就是睡了，所有会话一起停。
8. **做梦依赖模型**：模型不给内容时这一段梦就跳过，不会硬编。
9. **爬楼是一次性的**：醒来只翻一遍，翻完就标记已读，不会反复追问。
10. **手机端功能面小于桌面端**：形象库、记忆 M3 汇总、记忆分级规则、好感度编辑、
    记忆时间线这几块目前只有桌面端有入口。手机端走的是另一套独立实现（`mobile.js`），
    没有共用桌面端脚本，所以补齐功能要两边各做一次。
11. **面板资源要强刷**：前端文件带 `?v=` 版本参数，升级后如果看到的是旧界面，
    清一次缓存重进。

> 那些文件里有几个没设 `sys.path`，直接跑会 import 失败。

## 七、这一版修掉的坑

写在这里是因为它们都「看起来正常、实际不工作」，光看界面看不出来：

| 坑 | 后果 |
|---|---|
| `int(x or 3)` 读记忆等级 | `mem_level=0`（永久不可忘）被当成 3，实库 **157 条**禁区保护形同虚设。全插件 8 处都这么写 |
| `compose()` 遇到已有日记直接返回旧文 | 「重写日记」按钮点了没反应；就算绕过它，`INSERT OR IGNORE` 也会把新内容静默丢弃 |
| 主动消息注入时只按名字渲染 | 模型认不出那是自己说的话，会反问「什么没有」 |
| 归档名读配置里的静态人格名 | 系统提示跟随 AstrBot 人格、归档读配置，两条路分叉，模型把「绫」当别人 |
| 手机端 `qzone` 页读 `data.ok` / `data.usable` | 后端不返回这两个字段，未登录也显示「可用」，动态永远空白 |
| `config.list(...) or list(STRONG)` | 配置只要非空，代码默认收线词全作废（「睡觉去」就是这么无声失效的） |
| `close_minutes()` 没有调用点 | 「安静一会儿」是句空话，命中只改了一句提示 |
| 日记素材里直接喂「精力 100」 | 模型照抄成「精力是满的，100」，读起来像仪表盘读数 |
| `mobile.css` / `mobile.js` 没有版本参数 | 浏览器一直跑旧文件，改完东西手机上看到的还是老版本 |
| `openPage` 找不到页面时静默 return | 页面停在骨架，看起来就是「一直读取中」，且永远不知道卡在哪 |
