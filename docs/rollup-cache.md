# 爬楼分块缓存与阅读、补答分离

本次优化解决两个开销来源：后块失败导致前块重复阅读，以及只需要补全上下文时仍生成待回答清单。无需新增配置或数据库表；缓存写入现有 SQLite `kv`。

## 处理顺序

1. 日常回复仍先经过当前回复判定；允许回复后，从未读归档中冻结本批消息上界。
2. 依照现有条数和时间窗口分块，读取完整消息。默认仍是每块 45 条，没有增加历史总条数上限。
3. 根据是否需要补答选择阅读模式，逐块查询缓存；未命中才调用摘要模型。
4. 每块成功后立即保存结果。后块失败时保留整批未读，重试复用已经成功的有效缓存。
5. 需要补答时执行分流和正文生成；成功发送后立即记录回执。
6. 批次成功处理后才标记本批消息已读。阅读期间或失败后到来的新消息留到下一批。

原文、阅读结果、已读标记、发送回执分别保存；命中缓存不会自行标记已读，也不会自行发送消息。

## 两种阅读模式

| 场景 | 模型输出 | 后续补答 |
| --- | --- | --- |
| 普通活跃状态补上下文 | 简短 `summary`，输出上限 512 Token | 不提取清单、不分流、不生成历史补答 |
| 醒后关闭补答、名额已用完、当前批补答已发出 | 同上 | 同上 |
| 手动爬楼 | 同上 | 返回摘要，手动入口不额外发送补答 |
| 真正醒后待补课，补答开启且还有名额 | `summary` 和 `items`，输出上限 2000 Token | 分流后合并补答 |

纯阅读和清单提示要求话题摘要尽量控制在 100 字内；这不是截取原消息。长消息尾部仍进入模型输入。摘要之外由本地程序保留有界关键原句和消息 ID，详见 [摘要保真与原文核对](rollup-evidence.md)。

已取得足够的回复候选后，不再对后续块执行分流打分。这可减少后续块的 AtGuard 调用。当前消息本身的回复判定仍正常执行。

`rollup_session()` 的 `include_items` 单独控制清单提取；`read_only` 保留兼容用途，允许关闭补答时继续阅读。未显式传入 `include_items` 的旧补答入口维持原语义。

## 缓存边界

缓存键包含会话 ID、完整消息来源 UMO、存储人格标识、当前人格指纹、摘要模型指纹、全文分块指纹、提示版本和阅读模式。分块指纹包含消息 ID、时间、作者、正文等来源字段。换人格、改人设、换模型、换提供商、改端点或改原文会使对应缓存失效。

模型指纹仅使用提供商 ID、模型名、类型和端点，不读取密钥。无法确认模型或人格身份时，保守关闭缓存复用。

完整清单还绑定睡醒事件，避免下一次醒来直接沿用旧的“已答／过期”判断。同一事件和原文快照的失败重试可复用。纯摘要允许跨睡醒事件复用。

完整结果会同时保存不含 `items` 的纯摘要版本；纯摘要不能冒充完整清单。缓存保存摘要、清单的判定和来源指纹，以及每块最多 12 句、合计最多 1800 字的原文摘录；不复制完整消息。清单中的作者和问题正文每次按消息 ID 从本批原文回填。

缓存和提示版本为 3。命中缓存仍校验摘录与本批原文一致；补答前还会查询同会话存档，核实问题全文、关联全文与关键摘录，缺失或变化时保留未读。

有效期为 7 天，全库最多保留 256 条缓存记录；完整结果和纯摘要版本分别计一条。写入与过期、容量淘汰在一个事务内完成。过期、被淘汰或损坏的缓存会重新阅读原文。

缓存写入失败会中断本批，不标记已读。平台发送结果未知时仍禁止自动重发。

## 清除记忆

“删除所有记忆”的计数、确认、备份、删除与离线恢复均包含 `night.rollup.cache:`。缓存单独计数为 `rollup_cache_entries`，不混入记忆游标计数。

实际爬楼与摘要入口纳入已有记忆业务闸门：阅读进行中拒绝清除，清除期间新任务等待。清除后保留归档原文，但将旧记录标记已读；旧增量入口同样过滤这些已读记录，防止重新生成已清除的内容。

## 如何观察

成功批次新增日志，例如：

```text
[congling:rollup] L2 阅读 session=... mode=read chunks=3 cache_hits=2 generated=1
```

`read` 表示只读摘要，`items` 表示还提取补答清单；`cache_hits` 是命中块数，`generated` 是本次新生成块数。这些是调用计数，不是实际 Token 账单。

本次可减少重复输入调用和不必要的输出清单，首次完整阅读原文仍消耗输入 Token。512 是输出上限，不能据此宣称实际费用下降固定比例。
