# 完整未读爬楼与当前回复

本次将服务器已运行的完整未读处理整理至上游 1.1.1。普通回复的发送型准备钩子在
at_guard 请求判定之后执行：放行后阅读历史，补充本次模型请求背景，再回答当前消息。
`congling:wake_prepare_seconds` 仅报告准备耗时，消费方可自行选择是否扣除。

历史按 `msg_archive.handled` 读取，包括早于最近睡眠的遗漏记录；批次按归档 ID
冻结上界并排除当前触发消息。读取期间新到的消息保留到下一批。按配置分块，
长消息保留全文，摘要失败时保留未读和批次上界，重载或再次睡醒后仍可重试。

“爬楼机制”负责阅读；“醒后补课”负责从阅读结果挑选历史问题回复。补课关闭、
爬楼开启时仍读取并提供摘要。普通 awake 会话静默补充背景，只有本会话处于
waking 待爬楼状态时才发送爬楼提示和补课回复。提示按醒来事件去重，补课条数
限制累计到本次醒来；已解答、过期或不属于本块的模型输出不会进入补答清单。

完成阅读后，归档已读与有可核验消息来源的记忆未读标记在同一数据库事务提交。
未知来源、其他人格或会话的记忆保留原标记。线程事务取消时等待提交或回滚完成。
当前触发消息在发送后单独标记，at_guard 阻止发送时保留未读。

平台发送结果未知仍保留 sending/unknown 回执并停止自动重发；人格切换、
睡眠变化和记忆清除闸门沿用现有保护。回执保存阶段、人格与计数，不保存补课
回复正文。手动爬楼入口同样先阅读成功再确认已读。
