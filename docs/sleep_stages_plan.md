# 睡眠阶段（Sleep Stages）功能计划

> 目标：睡着时不再只有一个「睡着中」，而是能说出「刚入睡 / 浅层睡眠 / 深度睡眠 / 快速眼动」，
> 面板状态栏能看见，平台内部也按阶段决定「好不好叫醒、精力回多少、这会儿该不该做梦」。

---

## 一、为什么这么设计

三条硬约束，决定了实现方式：

1. **不能落库**。阶段如果存进 `NightState`，每次 tick 都要推进一次，插件重启、电脑睡眠、
   时钟跳变之后状态就会和真实时间对不上。所以阶段是**派生量**：
   `stage = f(sleep_at, now, 配置)`，纯函数，算一次就有，重启后自动正确。
2. **不能按 tick 精度推进**。现在的 tick 心跳可能一分钟一次、也可能十分钟一次（取决于谁调用），
   阶段边界如果靠「累加时间」会漂。用绝对时间求值就不受影响。
3. **要跟已有的东西咬合**。梦、精力、叫醒、醒来文案都已经写好，阶段不能自说自话，
   得挂到这些既有逻辑上，否则只是面板上多了个装饰。

---

## 二、模型：一个 90 分钟周期，整夜重复 4~6 次

真实睡眠结构的两条规律，照抄过来就够拟人了：

- **前半夜深睡多，后半夜 REM 多**
- **一个周期约 90 分钟**，越往后周期里深睡越短、REM 越长

第 `c` 个周期（`c` 从 0 起）内部按顺序走：

```
N1 刚入睡  →  N2 浅层  →  N3 深度  →  N2 浅层  →  REM 快速眼动
```

各段长度（分钟）：

| 段 | 公式 | 说明 |
|---|---|---|
| N1 | `8`（仅 c=0） | 第一周期开头才有，之后从 N2 起 |
| N3 | `clamp(36 * (1 - 0.28c), 4, 36)` | c=0 → 36 分钟，c=3 → 14 分钟，越来越浅 |
| REM | `clamp(10 + 6c, 10, 28)` | c=0 → 10 分钟，c=3 → 28 分钟，越睡越长 |
| N2 | `90 - N1 - N3 - REM`，拆成两段（深睡前 60%，深睡后 40%） | 兜底填满周期 |

第一周期示例（c=0）：`N1 8 → N2 21 → N3 36 → N2 14 → REM 10`，合计 89（零头并进下一段）。
第四周期（c=3）：`N2 17 → N3 8 → N2 11 → REM 28 → N2 26`，合计 90。

跨周期就是 `c = floor(t / 90)`，`pos = t % 90`，落在哪段查表即可。

### 午睡走另一条分支

`sleep_kind == "noon"` 且时长 ≤ 60 分钟时，只走 `N1 → N2`，末端视 `night.noon_dream_chance`
给一小段「轻 REM」（8 分钟）。这也解释了「午睡梦短、醒来只记得一句」。

### 边界情况

| 情况 | 处理 |
|---|---|
| `now < sleep_at`（时钟回拨） | 当作 N1，`t = 0` |
| `now >= wake_at`（该醒还没醒，tick 延迟） | 按最后一段算，`until = wake_at` |
| 提前叫醒 | 阶段表截到 `now`，不做「补完」 |
| `stage_enabled = false` | `snapshot()` 不返回 `stage`，前端整块不显示，行为回到现在 |

## 三、挂在哪些地方（这才是功能的价值）

### 1. 做梦：只在 REM（可开关）

现状：`Dreamer.due()` 只看「睡着满 N 分钟 + 间隔 N 分钟」。
改为：在原有条件上再加一条 `stage.key == "rem"`（配置 `night.dream_in_rem_only = true`）。

- REM 段通常 10~28 分钟，dream_loop 每 5 分钟扫一次，命中率足够
- 一场觉里 REM 段数 = 4~5，正好对应「一晚上做好几段梦」
- 配置关掉就退回现在的「按间隔」
- 好处：梦的时间分布终于跟「REM 期做梦」这个说法对得上，面板上也自洽

### 2. 精力恢复：按阶段加权

`energy.recover()` 现在只有一个 `per_minute`。tick 里改成乘一个阶段系数：

| 阶段 | 系数 |
|---|---|
| N1 | 1.0 |
| N2 | 1.2 |
| N3 | 2.2 |
| REM | 1.3 |

于是「睡一小时」不再线性等价：前半夜深睡那一小时补得多，后半夜 REM 补得少，
跟人早起还是困的感觉一致。

### 3. 叫醒难度：深睡最难叫

`Waker.check()` 算出的 `chance` 乘一个系数：

| 阶段 | 系数 |
|---|---|
| N1 | 1.3（刚躺下，一叫就应） |
| N2 | 0.8 |
| N3 | 0.45（深睡，喊不醒） |
| REM | 1.1（梦浅，容易惊） |

`WakeAttempt.reason` 里带上「她在深度睡眠，叫不太动」，日志和面板都能解释为什么没叫醒。

### 4. 醒来文案：从哪个阶段醒，语气不一样

`snapshot()` 返回 `woke_from`（醒来时所在阶段），`prompt_hint()` 据此加一句：

- N3 醒 → 迷糊、断片，「刚才是谁在说话」
- REM 醒 → 记得梦的碎片，可以顺口提一句
- N1/N2 醒 → 正常

### 5. 状态栏（前端）

`njNightHero` 在「睡着中」的标题下面加一行：

```
现在：深度睡眠 · 第 2 个周期 · 还有 1 小时 12 分
[███░░░░░]  ← 当前阶段进度条
```

「清醒中」不显示阶段。

### 6. 长夜 · 睡眠页

加一条整夜甘特条：横轴 `入睡 → 预计醒`，四段不同颜色，当前时刻一个游标。
下面四个小数字：`N1 8 分 / N2 3 小时 30 分 / N3 1 小时 36 分 / REM 1 小时 14 分`。
（数据来自 `stage_seq` 与 `stage_stats`，全是现算的）

## 四、接口与数据结构

`GET page/night/state`（`snapshot()`）新增三个字段，都是算出来的：

```jsonc
{
  "stage": {
    "key": "n3",
    "label": "深度睡眠",
    "since": 1793029080,      // 这一段开始的时间戳
    "until": 1793030520,      // 这一段结束
    "progress": 0.42,         // 当前段进度 0~1
    "cycle": 2,               // 第几个周期（从 0 开始）
    "index": 3                // 今晚第几段（从 0 开始）
  },
  "stage_seq": [              // 今晚整段序列，给甘特条用
    { "key": "n1", "label": "刚入睡", "start": 1793029013, "end": 1793029493, "cycle": 0 },
    { "key": "n2", "label": "浅层睡眠", "start": 1793029493, "end": 1793030753, "cycle": 0 }
  ],
  "stage_stats": { "n1": 8, "n2": 210, "n3": 96, "rem": 74 }   // 分钟
}
```

`stage_seq` 只生成到 `min(wake_at, now + 剩余)`，不预生成整晚，避免用户改起床点后数据不一致。

## 五、配置项（`_conf_schema.json` 新增一组 `night.stage`）

| 键 | 默认 | 说明 |
|---|---|---|
| `night.stage_enabled` | `true` | 总开关，关掉退回现在的「只有睡着中」 |
| `night.stage_cycle_minutes` | `90` | 一个周期多长 |
| `night.stage_n1_minutes` | `8` | 入睡期时长（仅第一周期） |
| `night.stage_deep_max_minutes` | `36` | 第一周期深睡上限 |
| `night.stage_deep_decay` | `0.28` | 每往后一个周期，深睡缩短的比例 |
| `night.stage_rem_base_minutes` | `10` | 第一周期 REM 时长 |
| `night.stage_rem_grow_minutes` | `6` | 每往后一个周期 REM 增加几分钟 |
| `night.stage_rem_max_minutes` | `28` | REM 上限 |
| `night.stage_noon_light_only` | `true` | 午睡只走浅睡分支 |
| `night.dream_in_rem_only` | `true` | 只在 REM 做梦 |
| `night.stage_energy_boost` | `{n3: 2.2, rem: 1.3, n2: 1.2, n1: 1.0}` | 精力恢复系数 |
| `night.stage_wake_penalty` | `{n3: 0.45, n2: 0.8, rem: 1.1, n1: 1.3}` | 叫醒概率系数 |

## 六、实施步骤（每步可独立跑通、独立合入）

### 第 1 步：纯函数 + 测试（不动任何现有逻辑）

- 新增 `night/stages.py`：
  ```python
  STAGES = {"n1": "刚入睡", "n2": "浅层睡眠", "n3": "深度睡眠", "rem": "快速眼动"}

  def build_plan(config, *, sleep_at, wake_at, kind) -> list[dict]:
      """整段计划：[(key, start, end, cycle), ...]"""

  def at(config, *, sleep_at, wake_at, kind, now) -> dict:
      """某一时刻处在哪个阶段（含 progress / cycle / index）"""

  def stats(plan) -> dict:      # 各阶段总分钟数
  def seq_from(plan, now, horizon) -> list[dict]
  ```
- `tests/test_sleep_stages.py`：周期边界、午睡分支、时钟回拨、`now > wake_at`、
  四个阶段总时长 = 睡眠总时长（不重不漏）

**验收**：新测试全绿，旧测试一行不改也全绿。

### 第 2 步：接进 `snapshot()` + 状态栏

- `NightService.snapshot()` 加 `stage` / `stage_seq` / `stage_stats`
- `njNightHero`：睡着时标题下面加一行阶段 + 进度条（样式沿用 `.nj-ring` 那套色）
- 未开启时字段不存在，前端 `if (st.stage)` 判断，不显示

**验收**：面板睡着时能看到「现在：深度睡眠 · 第 2 个周期」，清醒时不显示。

### 第 3 步：联动（梦 / 精力 / 叫醒 / 醒来文案）

- `dream_tick()` 加 REM 判断（`night.dream_in_rem_only`）
- `tick()` 的 `energy.recover()` 乘阶段系数
- `Waker.check()` 乘阶段系数，`reason` 带上阶段说法
- `_do_wake()` 记录 `woke_from`，`prompt_hint()` 按阶段给语气

**验收**：日志里能看到「REM 段做了一段梦」「深睡时没叫醒（系数 0.45）」；
叫醒测试里 N3 明显比 N1 难。

### 第 4 步：睡眠页甘特条 + 配置面板

- `njNightSleep()` 加整夜阶段条、当前游标、四段时长
- `_conf_schema.json` 补 `night.stage*` 一组，`njNightSettings` 给出可调项

**验收**：睡眠页能看到一整晚的结构，改周期长度后图跟着变。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 阶段算错导致「睡了三小时还在刚入睡」 | 纯函数 + 边界测试；`stage_seq` 首尾时间与 `sleep_at / wake_at` 严格对齐 |
| 做梦改成只在 REM 后，某些觉一段梦都没有 | 保留 `night.dream_in_rem_only=false` 回退；另外 REM 命中率不足时，在「浅睡末端」补一次低概率 |
| 叫醒系数让用户觉得「叫不醒」 | 系数只是乘在原有概率上，`need` 次数的兜底逻辑不变，攒够次数照样必醒 |
| 面板显示和实际不符（tick 停了） | 阶段是按 `now` 现算的，不依赖 tick 是否在跑 |
| 老数据没有字段 | `snapshot()` 缺字段时前端整块隐藏，不需要迁移 |

---

## 八、不做的事（划清边界）

- 不做「睡眠质量评分」「每周睡眠报告」这类统计面板——先把阶段做准再说
- 不做手动干预阶段（类似「让她进入深睡」的按钮），那是作弊，破坏拟人的感觉
- 不改 `NightState` 的持久化结构，阶段永远是算出来的
