# 摘要输出限制

`ModelHub.chat` 现在把调用方的 `max_tokens` 传给 `provider.text_chat`。
爬楼摘要保留原有的 2000 Token 参数；梦境和日记等同一入口保留各自限制。

部分 AstrBot 原生 OpenAI 兼容提供商虽然接受 `**kwargs`，却没有把其中的
`max_tokens` 写入请求。因此只增加关键字不足以控制实际消费。
本实现为该提供商的 `client.chat.completions.create` 安装一次透传包装：
在当前 `chat` 请求的上下文中，将限制写入最终 SDK 参数，
并从本次 `extra_body` 副本移除会覆盖限制的同名参数。

请求上下文用 `ContextVar` 隔离。并发调用分别使用自己的值；完成、异常及取消
都复位，不修改共享提供商配置。普通聊天没有该上下文时原样透传。
包装保留现有 SDK 计量和重试链，热重载可复用，不重复叠加。
没有此 SDK 入口的 API 路由直接接收 `text_chat(max_tokens=...)`。

输出限制可能让复杂摘要的 JSON 截断。现有摘要解析和未读确认规则继续生效：
无有效摘要时不视为成功处理，不用截断文本强行补成成功结果。
该限制约束供应商输出 Token，不等于最终发到聊天中的字符数；推理 Token
是否计入同一限制取决于具体模型接口。限额传输通过 SDK 请求体验证。

验证覆盖：参数透传、最终 SDK 参数、全局参数不被改写、并发隔离、
异常／取消清理、热重载复用、API 路由和非法参数。
另使用真实 AstrBot 提供商和 SDK 的本地假上游验证最终 JSON 请求体，
不调用付费模型，也不向真实聊天发送消息。
