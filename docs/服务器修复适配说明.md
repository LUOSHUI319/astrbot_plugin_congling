本次以官方 `main` 的 1.1.1 测试版（`99889a6`）为基础，迁移部署版本相对共同基线 1.0.1 的修复。保留上游的后台任务托管、结构驱动迁移、主体与会话引用、梦境提示使用预算、私聊隔离、全量记忆清除流程和独立手机界面；版本号沿用上游 1.1.1。

2026-11-03 重新读取服务器当前插件源码；相比此前快照，仅 `main.py` 增加消息 ID 兼容修复：优先调用 `get_message_id()`，旧版 OneBot 事件回退到 `message_obj.message_id`。该处理覆盖醒后流程、提示及回复收尾，避免缺少方法时中断回复。配置、数据库及本地尚未部署的完整未读爬楼改动不在本次服务器同步范围。

## 醒后发送流程

`NightState.last_wake_at / last_wake_reason` 与 `waking` 状态分别记录。超时退出 `waking` 只改变显示状态，不代表已经完成爬楼与补课。

普通回复和主动消息都调用 `night/wake_flow.py`：

1. 检查真实睡眠状态、睡眠周期与目标会话当前人格。
2. 有未读且开启爬楼时，先发送爬楼语。
3. 开启 `night.rollup.enabled` 后，对睡眠窗口内的消息分块摘要、打分并生成补课答复。
4. 补课成功发送后才推进压缩游标、未读标记与完成回执。
5. 普通回复继续处理当前消息；主动发送再生成并发送主动正文。

回执按会话和睡眠周期持久化。并发入口共用会话锁，成功阶段不重复发送。生成失败保留游标，允许下次重试；发送超时或取消可能已经产生平台副作用，记录未知结果并停止自动重发。本次回执只保存阶段进度与人格校验值，不保存补课正文。

`night.rollup.max_replies_per_wake` 限制同一会话本次醒来的问题总数，全部摘要块合计生效。待追问项目只保留判定结果，不额外启动小模型补判。

## 人格来源

`builtin / astrbot / none` 三种来源互斥，默认保持上游的 `astrbot`。普通回复、主动消息、模型生成的爬楼语和补课答复都解析同一份有效人格。

`PersonaService.resolve()` 返回身份、完整人设、开场对话和校验值。指定人格不存在时暂停发言，不退回内置人设。生成后与发送前再次校验；中途切换或删除角色会撤销旧文本。归档和主动日志写入有效角色名称及 ID。

普通请求只替换框架已知的角色段和开场示例，保留工具与技能说明。关系、实际作息、场景、记忆及醒后提示继续使用临时内容块；保留新版关于自述行为和私密梦境的恒定规则。`persona_id` 是旧记忆兼容标识，仍不可修改。

## 作息与收线

- 精力达到配置上限时提前自然醒，保留完整唤醒与爬楼链路；到点自然醒仍使用实际计划起床时间，避免延迟心跳重新激活已过期提示。
- 已经醒着时重复叫醒，不创建新周期，也不降低精力。
- “想继续睡”仅用于本次被消息或手动叫醒且精力未满的场景；每轮静默认领一次。新消息、超时或人格切换会撤销旧文案，不自动重新入睡。
- 强档入睡关闭时跳过强档收线。待入睡任务绑定原会话和原消息，并在发送后再次检查开关、有效期与是否继续聊天。
- “停”“安静”“闭嘴”等短指令必须整句表达收线，避免普通话题中包含一个“停”字就触发。

## 精力日志与配置页面

新增 `night_energy_log`，记录精力扣除、时间恢复、入睡、唤醒与收线判定。保留七天且最多两万条；精力上限处没有实际变化的恢复不重复记账。记录失败不阻塞聊天链路。

桌面页面新增精力日志、筛选、翻页和趋势。醒后补课配置说明包含十二项参数，可搜索并查看未保存的当前填写值；关闭后恢复原焦点。保留上游 1.1.1 的日夜皮肤和独立 `mobile.html` 入口，不恢复已删除的旧响应式样式及布局切换脚本。

手机人格页显示实际生效来源，「选择人格来源」进入人格设置，可修改 `persona.mode` 和 `persona.astrbot_persona_id`；内部兼容 ID 仍只读。精力日志和补课配置说明可通过「打开完整桌面面板」访问；`?desk=1` 防止被自动送回手机界面。

`night.rollup.mirror_livingmemory` 是尚未接入的预留参数，页面明确标注。它与下述普通记忆镜像桥是两个配置。

## 可选记忆桥与空间接口

`bridge_livingmemory.enabled` 默认关闭。开启后追加镜像具有平台和会话身份的普通事实，检索只接受匹配当前会话、平台及内部人格标识的镜像；缺失受众信息的旧记录及私人自述不会放行。镜像写入参与本插件的记忆清除闸门，避免卸载后残留写任务。外部 LivingMemory 库中的副本需在外部库单独管理和删除。

记忆列表保留新版全部身份字段，移除不用于页面展示的二进制向量，避免序列化错误。媒体解析超时从六秒调整为十二秒；视觉模型继续使用插件模型配置，不绑定部署实例的 provider ID。

QQ 空间优先使用客户端提供的原生动作；明确成功的发布同样写入新版行为证据。原生写入结果未知时停止，不用 HTTP 重发。定时说说按分钟检查，到点漏过的时段逐次补执行；后台循环使用 `spawn_background`，退出时统一取消并等待。

离线验证使用临时 SQLite、框架替身和模拟平台，不连接生产会话：

```bash
python -B tests/run_round3_p3.py
python -B tests/run_round4_p4.py

python -B tests/test_wake_persona_flow.py
python -B tests/test_server_adaptation.py
python -B tests/check_persona_mode.py
node tests/verify_server_ui.cjs
```

原有 HTTP 测试需要 AstrBot 自带的 `aiohttp`；独立运行时可在测试虚拟环境安装。浏览器测试需要可选 `playwright-core` 和 Chromium，可用 `PLAYWRIGHT_MODULE` 与 `CHROME_PATH` 指定路径，不增加插件运行依赖。

升级前备份插件配置和 SQLite 数据目录，再重载插件。新增归档列按实际结构补齐，旧字段和记忆正文保留；回退代码时额外列可保留，无需删除数据库。若发生平台发送未知结果，应先核实聊天或空间记录，再决定后续处理，不直接清空回执盲目重发。

此分支验证针对 1.1.1 适配代码；部署版本上的真实消息验证不能替代该分支在不同 AstrBot / OneBot 客户端组合中的验证。合并与正式发布由维护者决定。
