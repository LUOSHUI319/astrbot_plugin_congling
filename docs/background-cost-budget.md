# 后台请求成本预算与每日反思

## 触发原因

小时维护会反复调用 `Maintenance.reflect()`，旧实现没有使用 `memory.reflect_hour`，也没有按日跳过已有反思。抽取、反思和画像直接调用 `provider.text_chat()`，未设置输出预算；部分原生适配器还会丢弃传入的额外参数。

## 调用预算

| 调用 | 输出上限 | 请求时限 | 失败处理 |
| --- | --- | --- | --- |
| 记忆抽取 | `max(2048, max_atoms * 256)`；默认十条为2560，最多三十条为7680 | 90秒 | JSON无效或请求失败时不推进抽取水位 |
| 用户反思 | 512 | 每人60秒 | 保留旧反思，下一次小时调度可补跑 |
| 用户画像 | 1024 | 60秒 | JSON无效时不覆盖已有画像 |
| 纯阅读摘要 | 原有512 | 沿用阅读流程 | 保留未读及有效分块缓存 |
| 含补答清单的摘要 | 原有2000 | 沿用阅读流程 | 保留未读，补答仍核对同会话原文 |

原有抽取输入预算为6000字符，反思按完整条目选择最多6000字符，画像沿用原有输入限制。摘要沿用当前分块策略，不通过裁掉未读消息来降低费用。

这些都是后台生成任务。仅对支持该参数的 `deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-pro` 请求添加 `thinking: {"type":"disabled"}`，其他模型只设置输出上限。模型种类、用户记忆与当前人格不变。

## 参数落实与并发

`provider_request_budget()` 保留原函数中的 `text_chat` 调用位置，使费用采集继续归到抽取、反思、画像与摘要路由。原生适配器丢弃参数时，在最终 SDK 的 `chat.completions.create()` 边界落实上限及思考参数；没有 SDK 的路由直接接收参数。

预算保存在 `ContextVar`，每次退出、异常和取消都会恢复。请求体使用副本，共享提供商配置不被修改，其他协程的主对话不会收到后台参数。包装器保留自身标记，热重载复用，避免层层叠加。

抽取结果中提供的消息序号必须属于本批送入模型的用户消息，机器人消息和不存在的序号被拒绝；缺失引用的旧兼容返回沿用原逻辑，不能将这一校验视为对所有事实的完整验证。反思提示要求未知性别使用名字或TA，避免补充没有依据的身份。

默认的 `ModelHub.chat()` 行为保持原样，摘要调用显式传入 `background=True`；角色发言继续使用原有调用流程。

## 每日反思

每天配置小时之后允许补跑，例如默认4点开始；凌晨4点之前跳过。每个人已有反思缓存的 `ts` 属于当天时直接跳过，升级当天已有的反思也会被识别。

锁保存在当前 `Store` 对象上，多个 `Maintenance` 实例在同一进程中串行检查和生成。同日重启通过持久化缓存去重。只在拿到非空结果并成功保存后算完成；失败不会标记成功。缓存按人格和主体分开。

这针对当前单进程服务；多个独立进程同时使用同一数据库时，仍需额外的数据库租约，不能将进程内锁视为跨进程锁。每日去重意味着同一天新增加的认识留到下一日更新，原记忆抽取和召回继续运行。

## 验证与费用口径

`tests/test_background_budget.py` 的16项测试覆盖最终请求体、并发主对话隔离、异常与取消恢复、热重载、未知模型兼容、同日升级与重启、次日补跑、配置时间、人格隔离、抽取截断、机器人／未知引用和画像解析失败。

费用应分开看非缓存输入、缓存输入、输出，再按请求当时的单价计算。输出包含模型计费的思考 Token，不能用最终可见文本长度代替。用量未知的向量请求单独列出，不能视为免费。

本次未增加模型重试；现有原生提供商重试机制保留，抽取、反思和画像通过外层时限限制等待。观察时应同时检查 SDK 实际尝试数、输出上限、抽取解析成功率和实际业务费用，而不只比较总 Token。
